# Research: 恢复可恢复 SSE 工具错误

**Feature**: 008-recover-sse-tool-errors  
**Date**: 2026-08-23

## Decision 1: 以事件属性区分可恢复工具错误和终止错误

**Decision**: 只有未完成且包含工具调用标识的 error 事件被记为可恢复工具错误；聚合器继续读取。明确完成的错误、没有工具调用标识的错误、协议错误，以及流结束时没有完整非空答案的情况保持失败。

**Rationale**:
- IntelliQ 智能体可在工具失败后自行修正参数或知识标识，并在同一 SSE 流中产生后续 tool result、answer 和 complete。
- 工具错误不必然代表会话失败；终止性错误和无答案流仍不能作为有效评测回答。
- 该规则直接映射用户提供的 SSE 事件判定表，且可用事件字段独立测试。

**Alternatives considered**:
- 所有 error 一律终止 — 拒绝；会错误丢弃已恢复的完整答案。
- 所有 error 一律忽略 — 拒绝；会把真正终止错误误记为成功或等待到流结束。
- 由 Smart Eval 重试工具调用 — 拒绝；工具调用属于 IntelliQ Agent 状态机，客户端重放会破坏会话语义。

## Decision 2: 保留去重、非敏感的工具错误诊断

**Decision**: 为每条可恢复工具错误保留工具名称、工具调用标识、截断错误摘要和恢复状态；不保存原始工具参数。相同工具调用标识和错误摘要只保留一次。

**Rationale**:
- 最终成功并不意味着工具链稳定；诊断可支持上游模型/工具优化和报告审计。
- 原始 arguments 可能含敏感内容，且不需要用于判断恢复状态。
- 去重避免重连、事件重复或流重放导致报告膨胀。

**Alternatives considered**:
- 只保留错误计数 — 拒绝；无法定位是哪一个工具和错误类型。
- 保存原始 arguments — 拒绝；不必要地扩大敏感信息暴露面。
- 只记录服务日志、不保存结果 — 拒绝；报告无法区分恢复成功和未恢复失败。

## Decision 3: 用最终答案/完成事件决定成功

**Decision**: 非空答案在答案事件明确完成时可判为成功；若完成事件到达且已累积非空答案，也判为成功。仅出现工具结果、thinking 或 complete 而没有答案时失败。

**Rationale**:
- IntelliQ 流可能以完成答案或独立完成事件结束。
- 最终回答是评测可评分的最小条件；工具结果本身不是回答。

**Alternatives considered**:
- 必须同时要求答案完成事件和完成事件 — 拒绝；不同上游流实现可能只可靠提供其中一种完成信号。
- 任意 answer 片段即可成功 — 拒绝；流可能在答案未完成时断开。

## Decision 4: 诊断贯穿样本运行与报告

**Decision**: 扩展查询结果、样本运行持久化和报告详情，使恢复成功样本仍显示最终成功，同时暴露其工具错误诊断；历史记录没有该字段时按空诊断处理。

**Rationale**:
- 评测运行记录是排查上游工具稳定性的主要证据。
- 成功详情和失败详情必须使用一致的数据模型，避免报告遗漏恢复信息。
- 兼容空字段可让历史 SQLite 数据和已有报告继续读取。

**Alternatives considered**:
- 仅将诊断保存在内存 — 拒绝；任务完成后无法审计。
- 仅将诊断写入报告，不写样本运行 — 拒绝；任务执行期间和报告之间失去可追踪性。
