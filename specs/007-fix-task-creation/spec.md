# Feature Specification: 修复评测任务创建

**Feature Branch**: `007-fix-task-creation`

**Created**: 2026-08-23

**Status**: Draft

**Input**: User description: "解决无法创建评测任务的问题。创建任务时发生 RuntimeError: Event loop is closed。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 成功创建 IntelliQ 评测任务 (Priority: P1) 🎯 MVP

用户在数据集管理页面选择一个已验证的 IntelliQ 连接、智能体和适用知识库后，提交创建评测任务。系统能够完成智能体与知识库的校验并创建评测任务，不向用户返回“Event loop is closed”或服务器内部错误。

**Why this priority**: 此问题完全阻塞 IntelliQ 评测任务创建，用户无法进入评测执行和报告流程。

**Independent Test**: 使用一个配置为 `selected` 模式的 IntelliQ 智能体连续创建评测任务，验证每次均成功返回任务记录，且任务可进入后续执行流程。

**Acceptance Scenarios**:

1. **Given** IntelliQ 连接、智能体、知识库和数据集均有效，**When** 用户提交创建评测任务，**Then** 系统成功创建任务并返回任务标识，不返回未处理异常或 5xx 内部错误。
2. **Given** 智能体需要按配置筛选可用知识库，**When** 系统在创建任务前加载和校验知识库，**Then** 操作使用当前有效的异步资源完成，不因先前操作结束而失败。
3. **Given** 用户连续两次创建使用同一 IntelliQ 连接的评测任务，**When** 两次请求依次完成，**Then** 两次均可独立完成，不受前一次请求资源生命周期影响。

---

### User Story 2 - 获得可操作的创建失败反馈 (Priority: P2)

当智能体、知识库或 IntelliQ 服务确实不可用时，用户获得可理解的失败反馈，而不是 Flask 堆栈、事件循环错误或模糊的服务器错误。

**Why this priority**: 创建任务失败时，用户需要区分配置问题、权限问题和上游服务问题，才能采取正确行动。

**Independent Test**: 模拟智能体详情读取失败、知识库不可访问和连接不可用，验证系统返回结构化且可理解的错误结果，并且不会残留半创建任务。

**Acceptance Scenarios**:

1. **Given** IntelliQ 上游返回权限或可用性错误，**When** 用户创建评测任务，**Then** 系统返回明确的失败类别和用户可理解的信息。
2. **Given** 创建前校验失败，**When** 系统结束该请求，**Then** 不创建不完整的评测任务记录。
3. **Given** 任一创建请求失败，**When** 用户修正配置后再次提交，**Then** 新请求能够独立执行，不受之前失败请求影响。

---

### User Story 3 - 保持既有资源选择与评测流程可用 (Priority: P3)

修复任务创建后，用户仍可加载 IntelliQ 助手和知识库、选择数据集并创建后续评测；RAGFlow 和既有 IntelliQ 任务执行流程不受影响。

**Why this priority**: 资源加载、任务创建和评测执行共享连接能力，修复不能引入新的回归。

**Independent Test**: 分别验证 IntelliQ 助手/知识库加载、IntelliQ 任务创建以及非 IntelliQ 资源流程仍可正常完成。

**Acceptance Scenarios**:

1. **Given** 用户查看 IntelliQ 资源，**When** 加载助手和知识库，**Then** 资源列表仍按连接和智能体配置正确返回。
2. **Given** 用户创建任务成功，**When** 系统开始后续评测，**Then** 任务使用创建时选择的目标和知识库配置。
3. **Given** 系统存在其他 RAG 提供者，**When** 用户执行其原有流程，**Then** 不受 IntelliQ 修复影响。

### Edge Cases

- 用户在创建请求期间切换智能体或知识库时，系统只使用提交时的有效选择。
- 同一 IntelliQ 连接的多个创建请求先后到达时，各请求不共享已经失效的临时资源。
- 智能体配置为 `none`、`selected` 或 `all` 时，系统分别使用对应的知识库选择规则进行校验。
- 上游请求超时、权限不足或返回无效配置时，系统释放本次请求资源，并返回可理解错误。
- 任务创建成功但后续评测执行失败时，创建结果仍保持可追踪，不被误报为创建失败。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许用户为有效的 IntelliQ 连接、智能体、数据集和知识库创建评测任务，不得因内部异步资源已关闭而失败。
- **FR-002**: 系统 MUST 将每次任务创建请求所需的临时资源限定在该请求的有效生命周期内，不得复用已失效资源。
- **FR-003**: 系统 MUST 在创建任务前根据智能体的知识库选择规则校验用户选择的知识库。
- **FR-004**: 系统 MUST 支持连续创建使用同一 IntelliQ 连接的任务，且后续请求不受前一请求成功或失败影响。
- **FR-005**: 系统 MUST 在创建前校验失败时返回结构化、可理解的错误信息，并且不得写入不完整任务。
- **FR-006**: 系统 MUST 在上游权限、可用性或配置错误时保留可操作的错误类别，不得向用户暴露内部堆栈或事件循环实现细节。
- **FR-007**: 系统 MUST 保持 IntelliQ 助手和知识库加载功能可用，并保持其他 RAG 提供者的任务创建行为不变。
- **FR-008**: 系统 MUST 记录足以将任务创建失败关联到连接、智能体和知识库选择的非敏感诊断信息。

### Key Entities

- **评测任务创建请求**: 用户提交的连接、智能体、数据集、指标和知识库选择组合，在任务持久化前需完成校验。
- **临时连接资源**: 为一次 IntelliQ 资源读取或任务创建校验建立的请求级资源，仅在该次请求有效期内使用。
- **智能体知识库选择规则**: 智能体配置的 `none`、`selected` 或 `all` 模式，决定任务创建时可选择的知识库范围。
- **创建失败结果**: 未创建任务时返回的结构化错误，包含可理解类别和消息，但不暴露凭证或内部堆栈。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对有效 IntelliQ 配置连续创建 10 次评测任务时，10 次均成功创建任务，且不出现“Event loop is closed”。
- **SC-002**: 对已知的上游权限、连接和配置失败，100% 返回结构化错误结果，不返回未处理堆栈或通用内部服务器错误页面。
- **SC-003**: 创建前校验失败时，系统不产生可见的不完整评测任务。
- **SC-004**: IntelliQ 助手和知识库加载、IntelliQ 任务创建、以及其他提供者的任务创建回归场景均通过。
- **SC-005**: 正常网络条件下，用户提交有效任务后在 3 秒内获得“任务已创建”或明确失败反馈。

## Assumptions

- 已配置的 IntelliQ 连接具有读取智能体详情和当前租户知识库的权限。
- 用户选择的智能体及其允许知识库在创建请求期间保持有效。
- 本期仅修复任务创建阶段的异步资源生命周期，不改变评测任务运行时的模型超时、评分规则或报告内容。
- 现有任务与报告数据保留不变；只影响后续创建请求的行为。
