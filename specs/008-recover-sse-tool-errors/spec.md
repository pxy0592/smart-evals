# Feature Specification: 恢复可恢复 SSE 工具错误

**Feature Branch**: `008-recover-sse-tool-errors`

**Created**: 2026-08-23

**Status**: Draft

**Input**: User description: "Smart Eval 不应把所有 SSE error 事件立即判死；工具级可恢复错误应记录诊断并继续读取，最终得到完整答案时样本应成功。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 接受工具错误后的最终成功回答 (Priority: P1) 🎯 MVP

用户运行 IntelliQ 评测任务时，智能体可能在工具调用中先报告一次或多次错误，再修正调用并返回完整答案。只要后续流明确完成且已产生答案，系统将该样本记录为成功，而不是在首次可恢复工具错误时提前判定失败。

**Why this priority**: 当前行为会把能够自行恢复并最终正确回答的智能体样本错误计为失败，直接降低评测执行成功率并丢失有效答案。

**Independent Test**: 模拟包含两次工具错误、一次成功工具结果和最终完成答案的 SSE 流，验证样本完成、可进入评分，且保留两条工具错误诊断。

**Acceptance Scenarios**:

1. **Given** SSE 返回工具调用错误，错误事件未标记为完成且包含工具调用标识，**When** 后续仍有事件到达，**Then** 系统记录该工具错误并继续读取流。
2. **Given** 一个或多个可恢复工具错误后收到非空最终答案，**When** 答案事件明确完成或完成事件到达，**Then** 样本状态为成功并保留最终答案。
3. **Given** 可恢复工具错误后成功返回知识库内容和最终答案，**When** 评测报告生成，**Then** 工具错误作为诊断保留，不能覆盖样本成功状态。

---

### User Story 2 - 保持真正终止错误为失败 (Priority: P2)

当 SSE 流返回不可恢复的最终错误，或流结束时没有可用最终答案，系统仍将样本判为失败，避免把无效或不完整回答误记为成功。

**Why this priority**: 恢复工具错误不能降低失败识别的准确性。

**Independent Test**: 分别模拟最终错误、工具错误后无答案的流、以及无明确完成信号的空答案流，验证样本均失败并包含可理解的错误原因。

**Acceptance Scenarios**:

1. **Given** 错误事件已标记为完成，**When** 后续没有有效最终答案，**Then** 系统终止样本并记录失败。
2. **Given** 错误事件不属于具体工具调用，**When** 流未产生最终答案，**Then** 系统记录失败，不将其当作可恢复工具错误。
3. **Given** 流结束且未产生完整非空答案，**When** 系统汇总结果，**Then** 样本为失败。

---

### User Story 3 - 在报告中保留可审计工具诊断 (Priority: P3)

用户查看样本运行记录或评测报告时，可以区分“最终失败”与“曾发生工具错误但已恢复成功”的情况，并获得不含敏感信息的诊断摘要。

**Why this priority**: 工具稳定性问题仍需追踪；仅将恢复后的样本标成功会掩盖上游质量风险。

**Independent Test**: 对一个恢复成功的样本，验证结果中包含工具错误数量、工具名称和非敏感错误摘要，同时最终状态保持成功。

**Acceptance Scenarios**:

1. **Given** 样本在工具调用中发生可恢复错误后成功完成，**When** 保存样本运行结果，**Then** 结果包含工具诊断且不包含凭证、原始敏感请求或内部堆栈。
2. **Given** 用户比较恢复成功样本和最终失败样本，**When** 查看运行记录，**Then** 可以明确区分两者的最终状态和错误恢复情况。

### Edge Cases

- 同一工具调用重复上报相同错误时，系统避免生成重复诊断记录。
- 工具错误后直接收到完成事件但没有非空答案时，样本仍失败。
- 工具错误后收到多个答案片段时，系统合并答案，并以最终完成信号判断成功。
- 先收到可恢复工具错误、后收到不可恢复最终错误时，最终错误优先，样本失败。
- 非工具错误没有工具调用标识且未明确完成时，按终止性错误处理，避免无限等待或误报成功。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 将未完成且关联具体工具调用的 SSE 错误识别为可恢复工具错误，而非立即终止样本。
- **FR-002**: 系统 MUST 在记录可恢复工具错误后继续读取后续 SSE 事件，直到收到最终完成信号或流结束。
- **FR-003**: 系统 MUST 在后续获得非空完成答案时，将样本标记为成功并允许其进入评分流程。
- **FR-004**: 系统 MUST 在错误事件明确完成、非工具错误未恢复、或流结束且没有完整非空答案时，将样本标记为失败。
- **FR-005**: 系统 MUST 保留已恢复工具错误的非敏感诊断，包括工具名称、错误摘要和恢复结果。
- **FR-006**: 系统 MUST 防止重复的工具错误事件生成重复诊断。
- **FR-007**: 系统 MUST 保持现有引用、上下文、答案片段和完成状态的聚合行为。
- **FR-008**: 系统 MUST 不将凭证、完整内部堆栈或敏感工具请求参数写入样本诊断或报告。
- **FR-009**: 系统 MUST 保持真正终止错误、协议错误和无最终答案流的失败处理语义。

### Key Entities

- **SSE 事件**: 智能体流中的查询、工具调用、工具结果、答案、完成和错误事件。
- **可恢复工具错误**: 未完成且关联具体工具调用的错误；系统记录后继续消费流。
- **终止错误**: 明确完成、非工具且未恢复，或导致流无法产生完整答案的错误。
- **工具错误诊断**: 与样本运行关联的非敏感摘要，包含工具名称、错误摘要和是否已恢复。
- **样本最终结果**: 聚合后的成功或失败状态，包含答案、引用、上下文和工具诊断。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对包含至少两次可恢复工具错误后返回完整答案的测试流，样本 100% 标记为成功并保留最终答案。
- **SC-002**: 对最终错误、无最终答案或未恢复非工具错误的测试流，样本 100% 标记为失败。
- **SC-003**: 恢复成功样本中，每一条可恢复工具错误均可在诊断记录中辨识，且不重复。
- **SC-004**: 现有正常 IntelliQ SSE 成功流、引用聚合和真正错误流的回归测试均通过。
- **SC-005**: 评测报告能够将恢复成功样本计入执行成功率，同时保留其工具错误诊断。

## Assumptions

- IntelliQ 使用 `done` 字段表达事件是否已完成，并在工具级错误中提供工具调用标识。
- 非空完成答案或完成事件是判定最终成功的可靠信号。
- 上游智能体可能自行从工具错误中恢复，无需 Smart Eval 重放工具调用。
- 本期不修改 IntelliQ 的模型提示词、工具 schema、知识库内容或工具执行器实现。
