# Feature Specification: 新 RAG 系统接入

**Feature Branch**: `main`

**Created**: 2026-08-22

**Status**: Draft

**Input**: User description: "支持新的 RAG 系统：定义 API URL 和 API Key、获取知识库、上传数据集、获取对话助手、创建评测任务、获取评测报告。"

**External API Documentation**: [IntelliQ API 文档](https://ai-intelliq.peraglobal.com/platform/api-docs)；已确认契约摘要见 [references/intelliq-api-contract.md](references/intelliq-api-contract.md)。

## Clarifications

### Session 2026-08-22

- Q: 在当前 Smart Eval 尚无服务端用户角色鉴权的情况下，谁可以修改或测试 IntelliQ API URL 和 API Key？ → A: 使用部署级管理员令牌，仅授权管理员执行连接创建、修改、启停和测试操作。
- Q: 当一个评测任务中部分样本成功、部分样本因 IntelliQ 超时或流中断而失败时，任务和报告应如何处理？ → A: 任务完成并生成报告，仅评分完整成功的样本，同时展示失败样本数量、原因和整体成功率。
- Q: 创建 IntelliQ 评测任务时，知识库选择应如何遵循 Agent 自身的知识库选择模式？ → A: 遵循 Agent 的“全部、指定或不使用”模式；仅“指定”模式允许并要求用户选择一个或多个知识库。
- Q: 第一阶段上传评测数据集应正式支持哪些文件格式和单文件大小上限？ → A: 支持 JSON、JSONL、CSV、XLSX 和 XLS，单文件最大 10 MB。
- Q: IntelliQ 的 API URL 配置项应接受哪种地址格式？ → A: 同时接受服务根地址和以 `/api/v1` 结尾的 API 地址，由系统统一规范化，并拒绝 API 文档页面地址。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 配置并发现 RAG 资源 (Priority: P1)

作为持有有效部署级管理员令牌的系统管理员，我可以配置新 RAG 系统的连接地址和访问密钥，并查看该系统可用的知识库与对话助手，以确认 Smart Eval 已能够识别目标评测资源。

**Why this priority**: 连接配置和资源发现是后续评测流程的前置条件，也是验证新系统是否可用的最小业务闭环。

**Independent Test**: 使用有效配置完成保存，分别刷新知识库和对话助手列表，并确认列表内容来自当前选定的新 RAG 系统。该测试不依赖数据集或评测任务。

**Acceptance Scenarios**:

1. **Given** 管理员拥有新 RAG 系统的有效连接地址和访问密钥，**When** 管理员保存配置，**Then** 系统确认配置可用，并将该连接标记为可用于资源发现和评测。
2. **Given** 新 RAG 系统连接已配置且可用，**When** 用户打开知识库选择界面，**Then** 系统展示该连接下可访问的知识库，并提供明确的刷新结果。
3. **Given** 新 RAG 系统连接已配置且可用，**When** 用户打开对话助手选择界面，**Then** 系统展示该连接下可访问的对话助手，并保留其与知识库的有效关联信息。
4. **Given** 连接地址或访问密钥无效，**When** 管理员尝试保存或使用连接，**Then** 系统拒绝将其标记为可用，并显示可操作的错误信息且不泄露访问密钥。
5. **Given** 请求缺少有效的部署级管理员令牌，**When** 用户尝试创建、修改、启停或测试新 RAG 系统连接，**Then** 系统拒绝该操作，并且不向外部 RAG 系统发起请求。
6. **Given** 管理员输入服务根地址或以 `/api/v1` 结尾的 API 地址，**When** 管理员保存连接，**Then** 系统将其规范化为同一业务 API 基础地址，并确保后续请求只包含一次 `/api/v1`。
7. **Given** 管理员输入 `/platform/api-docs`、Swagger 页面或其他文档页面地址，**When** 管理员保存连接，**Then** 系统拒绝该地址并提示填写服务根地址或业务 API 地址。

### User Story 2 - 使用新系统创建评测任务 (Priority: P1)

作为评测人员，我可以上传符合要求的评测数据集，选择新 RAG 系统中的对话助手，并根据 Agent 模式选择知识库或使用 Agent 自身知识范围，然后创建评测任务，以便使用现有评测指标衡量新系统的回答质量。

**Why this priority**: 创建可执行的评测任务是接入新系统的核心业务价值，与连接配置共同组成首个可交付版本。

**Independent Test**: 在已有可用连接的前提下，上传一个有效数据集，选择该连接中的对话助手，按其“全部、指定或不使用”模式处理知识库，创建任务并确认任务进入可跟踪状态。

**Acceptance Scenarios**:

1. **Given** 用户拥有一个不超过 10 MB 的 JSON、JSONL、CSV、XLSX 或 XLS 数据集文件，**When** 用户完成上传，**Then** 系统验证、归一化并保存数据集，同时展示样本数量和数据完整性信息。
2. **Given** 新 RAG 系统连接、对话助手、符合其模式的知识库选择、数据集和至少一个评测指标均有效，**When** 用户提交评测任务，**Then** 系统创建任务并记录本次评测使用的系统、知识库选择模式、显式知识库（如有）、对话助手、数据集和指标。
3. **Given** 用户选择的知识库或对话助手不属于当前 RAG 系统连接，**When** 用户提交任务，**Then** 系统阻止创建并指出需要重新选择的资源。
4. **Given** 任务已创建，**When** 用户查看任务列表或任务详情，**Then** 用户可以看到任务状态、进度、已处理样本数和失败原因（如有）。
5. **Given** IntelliQ Agent 的知识库模式为“指定”，**When** 用户创建任务，**Then** 系统要求用户从该 Agent 有权访问的知识库中选择一个或多个知识库。
6. **Given** IntelliQ Agent 的知识库模式为“全部”或“不使用”，**When** 用户创建任务，**Then** 系统不要求也不允许手动选择知识库，并按 Agent 模式执行任务。

### User Story 3 - 查看新系统评测报告 (Priority: P2)

作为评测人员，我可以查找并查看针对新 RAG 系统生成的评测报告，以便分析整体得分、指标表现和样本级问题。

**Why this priority**: 报告完成评测闭环，但必须建立在任务已成功执行的基础上，因此优先级低于连接和任务创建。

**Independent Test**: 使用一个已完成的新 RAG 系统评测任务，打开报告列表并进入详情，确认任务来源、总体结果、指标结果和样本结果均可查看。

**Acceptance Scenarios**:

1. **Given** 新 RAG 系统的评测任务已完成，**When** 用户打开评测报告列表，**Then** 系统展示对应报告并明确标识其 RAG 系统、知识库、对话助手和数据集来源。
2. **Given** 用户打开一份报告，**When** 报告包含总体和样本级结果，**Then** 用户可以查看总体得分、各指标得分、样本输入、系统回答、参考信息和异常说明。
3. **Given** 任务仍在运行或已失败，**When** 用户尝试查看报告，**Then** 系统展示当前任务状态，并且不会将不完整结果误报为最终报告。
4. **Given** 系统同时存在原有 RAG 系统和新 RAG 系统的报告，**When** 用户筛选报告，**Then** 用户可以按 RAG 系统来源区分和查找报告。
5. **Given** 一个任务至少有一个样本完整成功且部分样本执行失败，**When** 任务结束，**Then** 系统将任务标记为已完成并显示警告，生成仅以成功样本为评分分母的报告，同时展示失败样本数量、原因和整体成功率。

### Edge Cases

- 连接地址为空、格式无效、不可达、响应超时或返回非预期结果时，系统不得将连接标记为可用。
- 连接地址包含 API 文档页面、Swagger 页面、用户信息、查询参数或片段，或者规范化后产生重复 `/api/v1` 时，系统必须拒绝保存并说明可接受的地址格式。
- 访问密钥为空、已过期、被撤销或权限不足时，系统必须区分认证失败与一般连接失败，并避免在界面、错误信息或可下载内容中暴露密钥。
- 部署级管理员令牌缺失、错误或已轮换时，连接管理操作必须在访问外部系统前被拒绝，且管理员令牌本身不得出现在错误信息或日志中。
- 新 RAG 系统返回空知识库列表、空对话助手列表、重复名称或缺失显示名称时，系统仍应以稳定标识区分资源并给出明确空状态。
- 资源列表数量超过单页容量时，用户仍应能够检索或逐页访问全部可用资源，不得静默截断。
- 已选知识库或对话助手在任务提交前被删除、禁用或失去访问权限时，系统必须在创建任务前重新验证并阻止无效任务。
- 上传的数据集为空、超过现有限制、格式不支持、字段缺失或部分样本无效时，系统必须说明失败范围，且不得创建引用无效数据集的任务。
- 文件扩展名不属于 JSON、JSONL、CSV、XLSX、XLS，或单文件大小超过 10 MB 时，系统必须在解析前拒绝上传，并清理任何临时文件。
- 对话助手未关联知识库，或关联关系与用户选择不一致时，系统必须阻止提交并说明冲突。
- Agent 的知识库选择模式在资源加载后发生变化时，系统必须在任务提交前重新验证，并清除或拒绝已不符合“全部、指定或不使用”模式的知识库选择。
- 任务排队或运行期间连接凭据被更新时，任务必须使用可追溯的一致连接身份，并在无法继续时记录明确失败原因。
- 新 RAG 系统限流、部分响应或中途不可用时，系统必须保留任务进度和诊断信息，且不得把缺失样本计为成功。
- 当部分样本失败但至少一个样本完整成功时，系统必须完成任务并生成带警告的报告；当没有任何样本完整成功时，系统必须将任务标记为失败且不生成最终质量报告。
- 报告生成前任务被取消或失败时，系统不得生成看似完整的最终报告。
- 原有 RAG 系统与新 RAG 系统存在同名知识库、对话助手或数据集时，所有选择和报告必须显示可区分的系统来源。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许提供有效部署级管理员令牌的请求新增和维护一个新 RAG 系统连接，包括连接名称、API URL、API Key 和启用状态。
- **FR-002**: 系统 MUST 将 API URL 和 API Key 作为必填连接信息进行校验，拒绝空白值、明显无效的地址以及无法完成认证的配置；API URL 可填写服务根地址或以 `/api/v1` 结尾的业务 API 地址。
- **FR-003**: 系统 MUST 在展示已保存连接时隐藏 API Key 的完整值，并确保任何页面、列表或导出接口都无法查看或导出该密钥。
- **FR-004**: 系统 MUST 在连接不可用时提供可操作的错误分类，至少区分地址不可达、认证失败、权限不足、超时和上游服务异常。
- **FR-005**: 系统 MUST 保留原有 RAG 系统的现有评测能力，并允许用户明确区分原有系统与新系统的资源和结果。
- **FR-006**: 系统 MUST 能够获取当前启用的新 RAG 系统连接下用户有权访问的知识库列表。
- **FR-007**: 知识库列表 MUST 至少提供稳定标识、显示名称和可用状态；当名称重复或缺失时，用户仍能准确区分和选择资源。
- **FR-008**: 用户 MUST 能够手动刷新、检索并选择新 RAG 系统的知识库；刷新失败时不得将旧数据误示为当前最新数据。
- **FR-009**: 系统 MUST 能够获取当前启用的新 RAG 系统连接下用户有权访问的对话助手列表。
- **FR-010**: 对话助手列表 MUST 至少提供稳定标识、显示名称、可用状态以及可获得的知识库关联信息。
- **FR-011**: 用户 MUST 能够手动刷新、检索并选择对话助手；系统 MUST 阻止选择已禁用或无权访问的助手创建任务。
- **FR-012**: 用户 MUST 能够上传 JSON、JSONL、CSV、XLSX 和 XLS 格式的评测数据集，单文件大小上限为 10 MB。
- **FR-013**: 上传成功后，系统 MUST 展示数据集名称、原始文件格式、样本数量、参考答案可用性、上下文可用性和校验状态。
- **FR-014**: 格式不支持、超过 10 MB 或内容无效的数据集 MUST 在任务创建前被拒绝，并向用户说明文件级或样本级的校验问题。
- **FR-015**: 用户 MUST 能够选择新 RAG 系统连接、对话助手、有效数据集和至少一个评测指标来创建评测任务；知识库是否需要选择由对话助手的知识库选择模式决定。
- **FR-016**: 系统 MUST 在任务创建前验证对话助手以及任何手动选择的知识库属于同一启用连接，并验证二者的关联关系和知识库选择模式仍然有效。
- **FR-017**: 每个评测任务 MUST 记录其 RAG 系统来源、连接身份、知识库、对话助手、数据集、评测指标和创建时间，以支持后续追溯。
- **FR-018**: 创建成功的任务 MUST 出现在任务列表中，并提供等待中、运行中、已完成、失败或已取消等明确状态。
- **FR-019**: 任务详情 MUST 展示处理进度、总样本数、已处理样本数、开始和完成时间，以及可操作的失败或取消原因。
- **FR-020**: 系统 MUST 为已完成的新 RAG 系统评测任务生成并提供评测报告。
- **FR-021**: 报告列表 MUST 展示并支持按 RAG 系统来源区分报告，同时保留现有的日期、知识库或其他已有筛选能力。
- **FR-022**: 报告详情 MUST 展示任务来源、总体得分、各评测指标得分、样本数量、生成时间和样本级评测结果。
- **FR-023**: 样本级结果 MUST 能够呈现问题、实际回答、参考答案或参考上下文（如数据集提供）、单项得分和异常说明。
- **FR-024**: 系统 MUST 防止运行中、失败或已取消任务的不完整数据被标记或展示为最终报告。
- **FR-025**: 所有资源选择、任务和报告 MUST 使用稳定标识建立关联，不得仅依赖可能重复或变更的显示名称。
- **FR-026**: 当新 RAG 系统暂时不可用时，系统 MUST 保留 Smart Eval 中已上传的数据集、已有任务记录和已生成报告，并清楚标识实时资源是否无法刷新。
- **FR-027**: 系统 MUST 对连接配置变更保留可审计信息，至少包括变更时间、受部署级管理员令牌认证的授权主体、可选的非可信调用者标签和受影响连接，但不得记录令牌或完整 API Key。
- **FR-028**: 系统 MUST 将新 RAG 系统返回的流式回答片段按顺序合并为单个样本答案，并且只有在收到明确完成信号后才将该样本标记为成功。
- **FR-029**: 系统 MUST 将新 RAG 系统返回的知识引用与对应样本结果关联保存，以支持需要上下文信息的评测指标和报告追溯。
- **FR-030**: 系统 MUST 隔离不同评测样本的对话上下文，防止一个样本的会话历史影响另一个样本的回答和评分。
- **FR-031**: 系统 MUST 将上游返回的思考过程、工具调用、工具结果或诊断事件与最终回答区分处理，不得将这些中间事件拼接为被评分的最终答案。
- **FR-032**: 当流式回答中断、返回错误事件或在未完成时关闭时，系统 MUST 将样本记录为未成功完成，并保留可诊断的失败信息，不得使用部分回答计算正常成功分数。
- **FR-033**: 系统 MUST 要求连接创建、修改、启用、停用和连接测试请求提供有效的部署级管理员令牌。
- **FR-034**: 当部署级管理员令牌缺失或无效时，系统 MUST 在访问外部 RAG 系统前拒绝请求，并且不得修改已保存的连接配置。
- **FR-035**: 系统 MUST 防止部署级管理员令牌出现在数据库业务记录、连接审计内容、任务、报告、页面响应和普通日志中。
- **FR-036**: 当任务至少有一个样本完整成功且部分样本执行失败时，系统 MUST 将任务标记为已完成并附带部分失败警告，同时生成最终报告。
- **FR-037**: 部分失败任务的质量指标 MUST 仅使用完整成功样本作为评分分母；失败样本 MUST 保留在报告中，并展示失败数量、失败原因和整体样本成功率。
- **FR-038**: 当任务没有任何完整成功样本时，系统 MUST 将任务标记为失败，并且不得生成看似有效的最终质量报告。
- **FR-039**: 系统 MUST 将 IntelliQ Agent 的知识库选择模式规范化为“全部、指定或不使用”，并在任务创建界面和任务来源记录中展示该模式。
- **FR-040**: 当 Agent 的知识库选择模式为“指定”时，系统 MUST 要求用户选择一个或多个该 Agent 有权访问的知识库，并拒绝空选择或越权资源。
- **FR-041**: 当 Agent 的知识库选择模式为“全部”或“不使用”时，系统 MUST 禁止手动知识库选择；“全部”按 Agent 的全部可用知识范围执行，“不使用”不向上游提交知识库 ID。
- **FR-042**: 当 Agent 的知识库选择模式缺失、未知或在提交前发生变化时，系统 MUST 阻止任务创建并要求刷新 Agent 配置，不得猜测模式。
- **FR-043**: 系统 MUST 将所有受支持的数据集格式归一化为统一的评测样本表示，只有在归一化和字段校验完成后才能将数据集标记为可用于创建任务。
- **FR-044**: 系统 MUST 将服务根地址和以 `/api/v1` 结尾的地址规范化为同一业务 API 基础地址，并确保构造的上游请求路径只包含一次 `/api/v1`。
- **FR-045**: 系统 MUST 拒绝 API 文档页面、Swagger 页面、包含用户信息、查询参数或片段的地址，并向管理员展示可接受的 API URL 格式。

### Key Entities

- **RAG 系统连接**: 表示一个可供 Smart Eval 使用的外部 RAG 系统，包含连接名称、规范化且不含 `/api/v1` 的服务根地址、受保护的 API Key、启用状态、可用性状态和最近验证信息；调用时由系统构造业务 API 基础地址。
- **知识库引用**: 表示从特定 RAG 系统连接发现的知识库，包含稳定标识、显示名称、可用状态和所属连接。
- **对话助手引用**: 表示从特定 RAG 系统连接发现的对话助手，包含稳定标识、显示名称、可用状态、所属连接、知识库关联及规范化的知识库选择模式（全部、指定或不使用）。
- **评测数据集**: 表示由 Smart Eval 管理的评测样本集合，包含名称、样本数量、数据完整性、参考答案和上下文可用性，以及校验状态。
- **评测任务**: 表示一次针对特定 RAG 系统资源执行的评测，关联连接、对话助手、知识库选择模式、零个或多个显式知识库、数据集和评测指标，并记录执行状态、进度和部分失败警告状态。
- **评测报告**: 表示已完成评测任务的最终结果，关联任务来源，包含总体得分、指标得分、样本级结果、生成时间和异常摘要。
- **连接变更记录**: 表示 RAG 系统连接配置的审计事件，记录变更人、变更时间、变更类型和连接标识，不保存完整访问密钥。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 具备权限的管理员可在 3 分钟内完成新 RAG 系统连接配置，并获得明确的可用或不可用结果。
- **SC-002**: 在新 RAG 系统正常且资源数量不超过 100 条时，95% 的知识库和对话助手刷新操作在 5 秒内向用户呈现结果或明确错误。
- **SC-003**: 对于不超过 10 MB 的有效 JSON、JSONL、CSV、XLSX 或 XLS 数据集，90% 的用户可在 2 分钟内完成上传、归一化、校验并看到数据完整性结果。
- **SC-004**: 90% 的评测人员可在首次尝试中正确选择新 RAG 系统资源、数据集和指标，并在 2 分钟内创建任务。
- **SC-005**: 100% 的任务创建请求都能阻止跨 RAG 系统连接混用知识库和对话助手。
- **SC-006**: 已完成任务的最终报告在任务完成后的 10 秒内可从报告列表访问，并正确显示其 RAG 系统来源。
- **SC-007**: 100% 的报告可追溯到唯一连接、对话助手、知识库选择模式、数据集和评测任务；仅“指定”模式要求保存具体知识库 ID 和名称快照，即使不同系统存在同名资源也不得混淆。
- **SC-008**: 100% 的界面、错误消息、审计记录和可下载内容均不显示完整 API Key。
- **SC-009**: 新 RAG 系统不可用时，用户仍可访问 100% 的既有数据集、历史任务记录和已生成报告。
- **SC-010**: 原有 RAG 系统的配置、资源发现、任务创建和报告查看核心流程在本功能上线后保持可用，现有验收场景无回归。
- **SC-011**: 100% 缺少或使用无效部署级管理员令牌的连接管理请求在访问外部 RAG 系统和修改配置前被拒绝。
- **SC-012**: 对所有部分失败但生成报告的任务，报告中的成功样本数与失败样本数之和等于总样本数，且质量指标分母等于完整成功样本数。
- **SC-013**: 100% 的 IntelliQ 任务创建请求符合所选 Agent 的知识库模式，“指定”模式至少包含一个有效知识库，“全部”和“不使用”模式不包含用户手动选择的知识库 ID。
- **SC-014**: 100% 的有效服务根地址和对应 `/api/v1` 地址被规范化为相同业务 API 基础地址，且 100% 的 API 文档或 Swagger 页面地址在保存前被拒绝。

## Assumptions

- 新 RAG 系统作为 Smart Eval 当前 RAG 系统之外的新增来源接入，而不是替换或迁移原有系统。
- 第一阶段支持一个已启用的新 RAG 系统连接；未来若支持多个同类连接，仍沿用连接身份隔离资源和结果的规则。
- 评测数据集继续由 Smart Eval 上传和管理，不上传到新 RAG 系统；新 RAG 系统提供知识库、对话助手及任务执行所需的回答能力。
- 评测报告继续由 Smart Eval 基于评测任务生成和管理，不依赖新 RAG 系统提供报告存储能力。
- 当前 Smart Eval 没有完整的服务端用户角色鉴权；本功能使用独立的部署级管理员令牌保护连接创建、修改、启停和测试操作，完整账号与角色权限系统不在本需求范围内。
- 第一阶段数据集格式固定为 JSON、JSONL、CSV、XLSX 和 XLS，单文件最大 10 MB；TXT 和其他非结构化格式不在本需求范围内。
- 新 RAG 系统能够通过提供的连接地址和访问密钥返回稳定的知识库与对话助手标识，并允许 Smart Eval 请求对话助手生成回答。
- 新 RAG 系统文档确认常规业务请求使用 API Key 认证，提供知识库列表、Agent 列表和基于 Agent 的流式问答能力；具体外部契约见功能目录下的接口契约参考。
- IntelliQ Agent 提供可解释为“全部、指定或不使用”的知识库选择模式；任务创建必须遵循该模式，而不是统一强制选择知识库。
- IntelliQ API URL 输入同时支持服务根地址和以 `/api/v1` 结尾的业务地址；API 文档页面和 Swagger 页面不能作为连接地址。
- 现有评测指标、任务队列、任务状态和报告展示能力可被复用于新 RAG 系统来源。

## External Dependencies

- IntelliQ API 文档页面是本需求的外部接口说明入口。
- 目标部署环境必须向 Smart Eval 提供可访问的服务地址、有效 API Key、知识库读取权限、Agent 读取权限和 Agent 问答权限。
- 文档说明部署环境的 Swagger 文档是最终权威契约，因此规划和实现阶段必须再次核对目标环境，而不能仅依赖示例字段。
- 外部系统采用流式方式返回回答；Smart Eval 的任务成功判定、重试和报告生成依赖完整消费该响应并识别明确完成状态。

## Scope Boundaries

### In Scope

- 新 RAG 系统连接配置和安全展示。
- 知识库与对话助手资源发现、刷新、检索和选择。
- 现有评测数据集上传与新系统评测任务创建流程的衔接。
- 新系统评测任务的状态、进度和失败信息展示。
- 新系统评测报告的列表、筛选、详情和来源追溯。
- 原有 RAG 系统与新 RAG 系统之间的资源隔离和兼容性保护。

### Out of Scope

- 将知识文档上传、同步或迁移到新 RAG 系统的知识库。
- 在 Smart Eval 中创建、编辑或删除新 RAG 系统的知识库与对话助手。
- 修改新 RAG 系统自身的模型、检索、提示词或权限配置。
- 新增评测指标、改变现有评分算法或重构任务调度策略。
- 批量迁移原有任务或报告到新 RAG 系统来源。
- 为新 RAG 系统开发独立的报告生成或存储服务。
